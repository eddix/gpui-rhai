# gpui-rhai 0.2.3

Release date: 2026-10-22. A patch release of 0.2 that is **not fully
compatible** with 0.2.2; read [Not compatible with 0.2.2](#not-compatible-with-022)
before upgrading. Runtime API stays **3**, gpui-pre/core/platform stay 0.3.7
and MSRV stays 1.95. Upgrade core, registry and CLI together.

It adds retained pages and navigation stacks, shared scrollbar sources and
tail-following collections, ColumnBrowser, Composer and selectable cards,
calendars, time inputs, time ranges and timelines, a native Markdown viewer,
recalibrated palettes, and CLI fixes that keep copied sources current; the full
list is in the [CHANGELOG](../../CHANGELOG.md).

## Not compatible with 0.2.2

- **Rust Hosts:** `PendingEvent` and `ActionInvocation` gain an `owner` field.
  Add `owner: None` to literals you build by hand, keep the owner on messages
  the runtime produced, and deliver them through the lifecycle's transactional
  event/action entry points.
- **Tables:** an Array-backed Table with an explicit `sort` now sorts in Rust,
  as NativeCollection Tables do, instead of keeping the caller's order.
  `sort.key` names the declared display column and an optional column
  `sort_key` names its scalar rank field. Remove a caller-side sort that
  duplicates it, or omit `sort` to keep an explicitly ordered Array.
- **Token base and palettes:** official components now use `control.border`
  and `control.danger_hover` / `control.warning_hover` /
  `control.success_hover`, which the token base derives from the palette's
  `on_danger`, `on_warning` and `on_success`. `gpui-rhai update` brings them
  into an unmodified or baselined `ui/tokens.rhai` (below). A hand-edited copy
  without a baseline must take the new lines from `registry/tokens.rhai`;
  otherwise the theme fails to load with `lacks tokens required by
  components/button`. A custom palette must define the three `on_*` colors;
  every bundled palette does.

## Upgrading from 0.2.2

### Copied official components and theme sources

Upgrade the CLI first: the 0.2.3 `gpui-rhai update` does what the 0.2.2 one
could not.

- **Same-version changes:** 19 official modules changed without a version
  change: `components/` `button`, `checkbox`, `code_viewer`, `combobox`,
  `command`, `date_picker`, `diff_viewer`, `icon_button`, `input`,
  `input_group`, `list`, `menu`, `popover`, `radio`, `split_pane`, `table`,
  `tabs`, `textarea` and `toggle_group`. The 0.2.2 CLI skipped such changes
  (this is how a pre-#140 SplitPane survived updates, #156); 0.2.3 compares the
  installed baseline with the bundled source and merges them.
- **Token base and palettes (#183):** `update` now merges `ui/tokens.rhai` and
  the bundled palettes in `ui/themes/` like components. A project from 0.2.0 to
  0.2.2 has no baselines for them: a copy equal to the registry gets one, a copy
  still exactly as one of those releases installed it is replaced, and any
  other is left alone with a `note:` line to merge by hand. `ui/theme.rhai`
  stays yours.
- **New modules:** `components/calendar`, `column_browser`, `markdown_viewer`,
  `selectable_card_group`, `time_input`, `time_range_picker`, `timeline` and
  `patterns/composer`, `navigation_stack`; install them with `gpui-rhai add`.

Merges keep local edits and write conflicts to `.gpui-rhai/conflicts/`.

### Behaviour to check

- Bundled palettes are recalibrated for reading contrast, and editable fields,
  choice marks and outline buttons draw the stronger `control.border`. Input
  placeholders use `text_muted` (an overridable `placeholder` part) instead of a
  fixed 55% opacity.
- SplitPane's default grip is an animated bar that grows from 24px to 40px. A
  drag is cancelled only when a committed change alters its interaction
  contract, not by unrelated rerenders.
- `gpui-rhai check` now resolves calls into the application's own modules
  (#184). It used to fail on any application with modules of its own, so
  running it may now report real findings it never reached before.
- `gpui-rhai embed` includes the application's own modules; regenerate the
  embedded module if the entry imports any.

### Hosts (Rust)

Additions, besides the `owner` field above:

- `ScrollbarSource`, `ScrollbarContext`, `ScrollbarSourceHandle` and source
  adapters for Host scroll surfaces; `VirtualCollectionScrollHandle` shares the
  tail-following state.
- `NavigateBack` and `ScriptViewHost::navigate_back`.
- `WallClock` / `WallClockSource`, time zones and `TimeRange` values, without
  the charts feature.
- `NativeTextDocument` registration on mounted views, the native Markdown
  viewer and a Host-owned `MarkdownPreparationCache`
  (`document_runtime_config().set_markdown_cache(...)`,
  `markdown_preparation_stats()`).

### Scripts

- Tabs `keep_mounted`, `patterns/navigation_stack` and `ctx.is_visible()`.
- `ColumnBrowser`, `patterns/composer`, `SelectableCardGroup`, Textarea
  `submit_key` / `on_submit` and `ctx.copy_text`.
- `Calendar`, `TimeInput`, `TimeRangePicker` and `Timeline`.
- `MarkdownViewer`.
- Collections' `follow_tail` and `on_follow_change`.
- SplitPane `handle`, `grip`, `handle_renderer`, `ctx.element_size`,
  `ctx.node_factory` and `render_node`.

## Known gaps

- A Host observer and stderr mirroring for script errors (#185) and a
  cubic-Bézier Motion easing (#186) land after 0.2.3.
