# gpui-rhai 0.2.2

Release date: unreleased. A compatible patch release of 0.2: Runtime API stays
**3**, gpui-pre/core/platform stay 0.3.7 and MSRV stays 1.95. Upgrade core,
registry and CLI together.

It adds Toast's stacked layout, a Host hook for the Rhai engine and a focus
event for scripts, and fixes what applications met on 0.2.1; the full list is
in the [CHANGELOG](../../CHANGELOG.md).

## Upgrading from 0.2.1

### Copied official components

`gpui-rhai update` brings `components/toast`, now at 0.2.2. It merges it with
local edits as usual and writes conflicts to `.gpui-rhai/conflicts/`.

### Behaviour to check

- `style().hidden()` on a `row` or `column` now hides it. Before, the node kept
  its room and paint; check any row or column that was hidden and still meant
  to show.
- Toast close buttons carry a 1px transparent border for the focus frame and
  round their hover fill with `radius.sm`.
- Messages of a `one_of` validation failure name the path inside each variant,
  and capability errors print the capability id plainly; code that matched the
  old text needs the new one.

### Hosts (Rust)

All additions; nothing existing changes signature:

- `ScriptViewExtension::configure_rhai_engine(&self, &mut rhai::Engine)`, with
  a default that does nothing, and the `gpui_rhai::rhai` re-export (#151); see
  [the user guide](../../USER_GUIDE.md#the-rhai-standard-library-in-view-scripts)
  for disabling `eval` and replacing every overload of `sleep` and `exit`.
- `impl Display for CapabilityId`.

### Scripts

- `node.on_focus_within_change(Fn)` and `node.on_focus_within_value(Fn, value)`;
  see the [component authoring guide](../component-authoring-guide.md).
- Toast props `layout`, `heading`, `clear_label` and `on_activate`, the
  `activate` event and the `stack_*` parts; see
  [Toast](../reference/components/toast.md).

## Known gaps

- #156 (absolute content in a SplitPane stage) does not reproduce on 0.2.1 or
  0.2.2; the issue stays open for the reporter to recheck.
