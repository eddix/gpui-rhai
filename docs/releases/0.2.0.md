# gpui-rhai 0.2.0

Not released yet. Runtime API moves to **3**; gpui-pre/core/platform remain
0.3.7 and MSRV remains 1.95. Upgrade core, registry and CLI together.

0.2.0 introduces a design system for productivity tools and separates it from
the runtime. The specification lives in [docs/design/](../design/); the
[Gallery](../gallery.md) is its acceptance application.

## What changes

**Runtime: neutral.** The runtime no longer knows any design vocabulary. Themes
are an open token registry; components declare the tokens and environment
values they read, and preparation validates the active theme against the
mounted components. Typography roles and lengths are open names; lengths can
vary with environment values (`density`, `size`) set by `.env(#{ ... })` and
resolved during native rendering. Color expressions (`mix`, `alpha`,
`readable`) evaluate after all layers merge. An application can bring its own
design without the official token base (`examples/byod_treemap`).

**L0: the token base.** `registry/tokens.rhai` (installed as `ui/tokens.rhai`)
holds the design language: CJK-aware typography (body 14/22), control roles,
the spacing scale and relationship aliases (`unit`, `related`, `group`,
`section`), `metrics.*` in comfortable and compact density, radius roles and
derived colors. Bundled palettes contain colors only.

**L1: 62 components rebuilt** on one set of contracts (size and density as two
axes, one content inset, a 2px ink focus frame, four marker silhouettes for
Button, Tag, Badge and Kbd, "normal is quiet" status color).

**L2: layouts and patterns.** `layouts/` (Stack, Inline, Toolbar, Region) and
`patterns/` (Section, DescriptionList, Stat, FormLayout, InlineState, DataView,
ListDetail, AppShell with F6 regions).

**Composition audit and profiles.** `ScriptViewHandle::composition_audit`
checks committed geometry: row height mismatch, text edges, nested spacing,
solid actions per group, mixed type in a row, painted contrast, unresolved
fonts. A profile (`gpui-rhai init --profile productivity`,
`EmbeddedScriptView::profile_source`) chooses the rules; without one only
correctness is checked.

**Keyboard.** Every interactive component is one tab stop; the runtime keeps
overlay trigger wrappers, key-routing containers and tooltip panels out of the
tab order.

**Gallery.** `gpui-rhai gallery` opens the new Gallery, a Rhai application on
AppShell with 83 pages, four keyboard scenes and a live audit count. Every page
passes the audit in both densities. Stories remain as development fixtures
behind `--story`.

## Migration from 0.1.x

### Hosts (Rust)

- Official registry components need the token base:
  `EmbeddedScriptView::new(...).token_base(gpui_rhai_registry::TOKEN_BASE_SOURCE)`.
  Projects using the CLI get `ui/tokens.rhai` from `gpui-rhai update`. Without
  it, preparation fails with the list of missing tokens.
- Optional: `.profile_source(...)` with the bundled `productivity` profile to
  enable the composition audit; `composition_audit(cx)` returns the findings.
- Removed from `gpui-rhai-cli`: the `gallery_app` module (the Rust Gallery
  shell). The `test-support` feature still exists and gates nothing. Removed
  from `gpui-rhai-registry`: `GALLERY_NAVIGATION_SOURCE` and
  `GALLERY_SOURCE_VIEW_SOURCE`. Added: `TOKEN_BASE_SOURCE`, `BUNDLED_PROFILES`,
  the `layouts/` and `patterns/` source tables and `GALLERY_SOURCES_BY_ID`.
- `gpui-rhai gallery --list` prefixes each line with `page` or `story`.
- To draw the title bar in Rhai, hide the platform bar in the window options
  (`TitlebarOptions { appears_transparent: true, traffic_light_position, .. }`)
  and, on macOS, also set `WindowOptions::app_owns_titlebar_drag = true`:
  without it AppKit still owns the title strip, so pressing a button in the bar
  starts a native window move and a quick double press zooms the window
  (headless tests cannot show this). Then allow drag areas for that view
  (`ScriptViewConfig::window_drag_areas` or
  `ScriptApplication::window_drag_areas`); see [embedding](../embedding.md).
  Other views keep drag areas inert.
- Theme lengths depend on environment values: `ThemeTokens.spacing` and
  `radii` hold `Variable<Length>` (a fixed value or a `by_env` table), no longer
  `Length`. A Host that reads a token for its own native chrome resolves it:
  `theme.tokens.resolve_length(Length::token("radius.md")?, &environment)`
  (`Environment::EMPTY` uses the declared defaults), or
  `Variable::resolve(&environment, &tokens.environment)` on a
  `length_token(...)`.
- Hosts that load user themes: palette themes are colors only. Spacing,
  metrics, typography and radius come from the token base; a radius
  preference is the `corners` environment value
  (`ThemeTokenOverrides::environment_defaults`), not a radius override.
  `load_theme_source` loads a palette alone, without the token base, so its
  result has no spacing and fails token requirements; validate a user theme
  with `load_theme_with_layers(engine, Some(&token_base), ...)` and
  `ThemeVariant::require`, as preparation does.
- `ScriptViewHandle::last_error` keeps a failure until a successful reload or an
  acknowledgement; a later successful event no longer clears it. A Host with
  its own error panel calls the new `ScriptViewHandle::clear_error` when the
  user dismisses it. Code that polled `last_error` to see whether the latest
  event worked should check the result of that event instead (automation
  commands return their own failure).

### Component source

- Module headers declare `"runtime_api": { "min_inclusive": 3,
  "max_exclusive": 4 }` (header and `define_component` metadata). Components
  should also declare `tokens` and `environment`; see the
  [authoring guide](../component-authoring-guide.md#metadata).
- Copied official components: run `gpui-rhai update` and review the conflicts;
  every component changed.

### Props and defaults

| Component | 0.1.x | 0.2.0 |
|---|---|---|
| Button | default `variant` `primary` | default `secondary`; set `variant: "primary"` on the one primary action; new `action`, `shortcut` |
| Badge | `dot` default `false` | `dot` default `true` (the square lamp); new `emphasis` (`subtle`/`strong`) |
| Card | `elevated` | removed; `variant: "outline"` for cards on a raised surface |
| Combobox | `row_height`, `trigger_height` | removed; use `size` (or an inherited `size` environment) and density |
| Command, CommandDialog | `row_height` | removed; rows follow `metrics.row`; items may bind `action` |
| Tag | — | new `facet` segment and `close_label` |
| Kbd | — | new `keys` and `appearance` (`keycap`/`inline`) |
| Tabs | — | new `panel` (false makes a view switcher) and `size` |
| Popover | — | new `align` (`start`/`center`/`end`) |
| Input, InputGroup, ButtonGroup, ToggleGroup | — | new `size` |
| Table | — | `numeric` columns; keyboard selection; frameless; a column without its own value shows only its adornments; a column's `typography` (`"code"` for identifiers); group headers in the label voice |
| Slider, RangeSlider | 240-wide track inside a stretching root | a 240-wide unit; give the `root` part a width to change it |
| Icon | declares check, close, search | also help, info, warning |
| TitleBar | subtitle on a second line | title and subtitle on one line |
| Menu, ContextMenu, IconButton, Tooltip | — | new `action` |
| FormLayout (new) | — | controls keep their own width (give wide fields a `width`); helper text sits a `unit` under the control |
| DataView (new) | — | footer fields sit a group apart; loading and empty states replace the body; `toolbar.fill`, `toolbar.size` and `inset` reach Toolbar and Region |
| Toolbar (new) | — | `fill` takes the width between the groups (a search or query field); a field in `filters` is as wide as its content |
| Region (new) | — | the body clips; `scroll: true` scrolls it; `external_title` for a title drawn elsewhere |
| Resizable | `resize` payload `{x,y,width,height,handle}` | `{x,y,width,height}`, the next `rect` as is; store it directly |

### Themes

A copied `ui/tokens.rhai` must declare the `corners` environment value
(`gpui-rhai update` brings the new token base): official components that read
radius tokens declare it, and preparation fails with the missing value
otherwise. To ship a corner style, set its default in the token file or with
`ThemeTokenOverrides::environment_defaults`; `.env(#{ corners: ... })` changes
it for a subtree.

Palette themes should contain colors only. Typography, spacing, metrics and
radius come from the token base; a 0.1 theme that still defines them overrides
the base and opts out of "switching palette never changes layout". Spacing
gains `xl`; typography roles change size (body 14/22, caption 12/18) and add
`control_small`, `control_regular` and the mono `label` voice. Derived colors
(`table.selection`, `tabs.foreground`, `text.*`, `control.hover`, `tag.facet`,
`scrollbar.*`) are computed by the token base and may be overridden by name.

### Application scripts

- Components inside a virtual item (Table rows, VirtualList and Sortable items)
  now have an `Item[<item key>]` segment in their instance path. Their state
  resets once after the upgrade; diagnostics and Host lookups that spell such a
  path gain the segment. A component key inside a row no longer needs the row
  key in it.
- SplitPane slot content sits in a sized wrapper (since 0.1.8, which keeps the
  caller's node identity): a `start` or `end` node that relied on receiving the
  pane size now sizes to its content. Make slot content fill its wrapper
  (`width(relative(1.0)).height(relative(1.0))`), notably a SplitPane nested in
  another.
- Do not name script functions after built-ins (`index_of`, `contains`,
  `filter`, `split`, …): Rhai resolves a script function before a built-in, also
  inside imported components; `x.f(a, b)` reaches a script `fn f(a, b)`.
  `gpui-rhai check` now warns about such entry functions (`builtin-shadow`).
- Prefer layouts and patterns over hand-written rows with literal sizes; the
  productivity profile reports literal geometry in application source.
- A Region body taller than the region is clipped, not scrolled (0.1 page
  helpers usually scrolled): set `scroll: true`, or let a Table or virtual
  list scroll itself.
- Overriding Table's `group_label` part for a quieter group header is no longer
  needed: group headers use the label voice. An overlay panel that holds focus
  itself shows a 2px frame; restyle or hide it through the `focus_frame` part
  of Dialog, Sheet, Popover, Menu, DatePicker or Combobox.

## Field reports

Both were checked against this branch without changing the projects.

**disktree-rhai** (a 0.1.8 application with its own design, no official
components). Built in a temporary copy through `cargo --config` path
overrides. Three changes were needed:

1. `runtime_api` 2 → 3 in `app.toml` and module headers: the only change caused
   by 0.2.0.
2. `ScriptViewHost::new_with_policy` → `new`: the project used an API that never
   shipped in a release; it loses its window-close `q` policy.
3. `.expression_depth_limits(64, 128)` on the Host: the 0.1.8 defaults (64/32)
   are unchanged and its deep view functions exceed 32.

With these, its 45 tests passed and its own skin rendered unchanged: the
runtime carries no design assumptions.

**oh-my-byted** (pins `=0.1.7`, uses registry components). A read-only scan of
its sources at `4733fb0` (2026-10-01) finds what an upgrade needs; nothing was
built or run:

- `bins/omb-gui`: add `.token_base(gpui_rhai_registry::TOKEN_BASE_SOURCE)` to
  each of the four `EmbeddedScriptView::new` assemblies in `src/main.rs`;
  consider the `productivity` profile.
- Widgets with their own components (`examples/demo/widgets/tasks`,
  `controls`) declare `runtime_api` 2..3; change to 3..4.
- Seven widgets pass `trigger_height: ui::control_h()` to Combobox (ten
  calls); remove it. `stdlib/ui.rhai` hard-codes geometry (`control_h() = 28`,
  fixed widths, its own `page` and `toolbar`); compact density already gives
  28px controls, and Region, Toolbar and DataView replace the helpers.
- All fourteen `Button(#{ ... })` calls already set `variant`, so the new
  `secondary` default changes nothing there.
