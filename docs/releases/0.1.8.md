# gpui-rhai 0.1.8 candidate

Not published yet. Merge, crates.io publication and tag require approval of the
exact candidate. Runtime API remains 2, gpui-pre/core/platform remain 0.3.7,
and MSRV remains 1.95.

## Direct manipulation and collection model

The 62-component registry adds Draggable, DragSource, DropZone, Sortable,
PanZoom, Rotatable, SelectionArea, RangeSlider and Tree. Resizable and SplitPane
retain their distinct responsibilities on the shared interaction foundation.
Move/wheel/preview/auto-scroll stay native. Controlled rejection, source changes,
Escape, deactivation, suspend and disposal cancel through one ownership model.
Virtualized sources retain logical membership; clip/occlusion govern drop targets.

Virtual batches merge scoped state deltas and publish one final invocation graph.
Transparent returns and parent/child/sibling updates preserve valid state,
callbacks and resources; failures retain last-good snapshots. Tracked reads
separate executable owners from per-item contributions, so scroll history does
not accumulate subscriptions. Logical ElementRef subscriptions follow binding
appearance/replacement/removal and detach old-node observations.

Table uses one viewport-based fixed/percent/flex/native-width plan and actual
horizontal content extent. Header/body remain aligned, RTL tail columns are
reachable, four body states retain geometry and logical offset, and final/sole
columns support resize/autofit. Measured sizes demand bounded native follow-up
frames without extra Rhai. Node Style storage is shared and copy-on-write.
Locale direction changes retain the same logical scroll distance in both
directions, with range clamping. Caller-applied Table layout markers follow
the existing component presentation replay contract across incremental updates.

## Host integration

- PreparedScriptView::mount_window explicitly delegates a native window to one
  script command owner; ordinary embedded views stay restricted. Commands retain
  enqueue origin and target reservation through peer pumps and deferred work.
  Disposal, last Handle drop, native closure and replacement revoke stale work.
- Operation quota and expression-depth policy are independent Host settings.
  Defaults remain 1M operations/global64/function32; zero normalizes to one.
  Extensions run after builder policy; reload candidates use independent storage.
  Quotas are cooperative, not frame-time guarantees or native-code deadlines.
- ctx.theme_variant() returns lightweight family/name/mode or unit. Render reads
  track theme; effects restart only through explicit deps. Actual native
  appearance precedes primary/secondary init and effects without replaying init.
  Native notifications wake idle views; suspension retains the environment and
  disposal releases the weak subscription. Token-only UI repaints without Rhai.
  Headless System resolution explicitly defaults to Dark until native information.
- Node key names use one canonical ASCII identifier or punctuation rule and real
  Capture/Target/Bubble dispatch. Matching uses GPUI key (with existing logical
  RTL arrows), not key_char; modifiers are not filtered. Exact chords use Host
  actions. Disabled, Enter/Space fallback and Host Escape ownership remain tested.
- Mutable images use the existing bounded foreground Host bridge or immutable
  versioned IDs; no strong per-asset revision protocol or automatic version-stream
  eviction is promised. See [Host bridge](../asset-refresh-host.md).

## Breaking integration checklist

1. Upgrade core, registry and CLI together and review copied source updates.
   Table source0.1.8 uses new native column-plan builders; Runtime API2 alone does
   not make it usable with an older SDK.
2. Rust MAX_SCRIPT_OPERATIONS becomes DEFAULT_SCRIPT_OPERATION_LIMIT without an
   alias. ExecutionTiming literal initializers add operation_limit and
   round_operations; operations keeps its timing-span delta meaning.
3. WindowCommandRegistry drains qualified QueuedWindowCommand records; read the
   payload through command(). Open→Focus/Close uses one pending reservation;
   the obsolete NotOpen error is removed.
4. Key strings no longer trim whitespace; segment max60/full event max64.
   Use named space. Chords and multi-punctuation names are rejected.
5. Keep position/order/transform/selection/range/expansion controlled. Delegating
   native window policy replaces its close interceptor; retain ordinary mount
   when Rust must own that policy.
6. Read theme metadata in render and pass it to effect deps. Body-only reads do
   not restart effects. Host quota policy is documented in [Performance](../performance.md).

## Source-backed acceptance scenarios

```text
gpui-rhai gallery --story workbench/interaction-lab
gpui-rhai gallery --story components/table --case wide
gpui-rhai gallery --story components/table --case wide --locale ar
gpui-rhai gallery --story components/table --case loading
gpui-rhai gallery --story components/table --case projected-empty
```

Table scenarios support real sort/selection/resize and show resolved metadata.
Host collection register/replace is public. CLI check honestly reports
unexecuted Host-dependent init/view instead of fabricating capability data.
Map/array defaults use recursive UiValue tags and field-specific diagnostics.
Generated embedded manifests use immutable bindings for both empty and nonempty
capability lists, so generated consumers can build with `-D warnings`.

## Boundaries and release status

OS/file and cross-window drag, DockLayout and 3D remain outside this release.
#83 custom grip, #89 Table context request, #91 general invocation origin and
#95 monospace/column typography are separate 0.1.9 designs. #14 JIT integration
is excluded; research and original branches remain preserved.

macOS/Linux X11/Wayland results belong to the exact candidate verification
manifest. Simulated IME is not OS preedit acceptance; fixed Dark is not native
SystemDark testing. Real-machine/manual/120Hz/visual gaps remain pending until
supported evidence exists. CI and core checkpoint approval do not authorize
publication.
