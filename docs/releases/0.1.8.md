# gpui-rhai 0.1.8

0.1.8 completes the unified Interaction Runtime and direct-manipulation
component line. It retains Rhai Runtime API **2** and the gpui-pre 0.3.7 package
family from 0.1.6.

## New component surface

- `Draggable` changes one controlled position with handle, axes, containment,
  snap, threshold and keyboard parity.
- `DragSource` and `DropZone` transfer bounded typed application payloads inside
  one Host. OS/file and cross-window drag remain Host/platform integrations.
- `Sortable` emits stable source/insertion-anchor proposals for bounded rich
  items and vertical virtual Array/NativeCollection data.
- `PanZoom`, `Rotatable` and `SelectionArea` provide controlled Canvas viewport,
  explicit-pivot rotation and keyed object selection over one affine paint/
  hit-test coordinate model.
- `RangeSlider` adds an ordered two-thumb interval over Slider's shared axis,
  step and RTL rules.
- `Tree` adds a validated Rust outline projection over public
  `virtual_collection`, with controlled expansion, selection and navigation.

The official registry now contains 62 editable source components. Component
schemas are pre-1.0 and intentionally use the final 0.1.8 contracts without
compatibility aliases.

## Runtime and performance model

- One `ScriptViewHost` coordinator owns native pointer sessions, application
  drag state, per-View capture routes, frame-local GPUI hitboxes and
  non-reentrant cancellation. Logical unmount and temporary virtualization are
  distinct, so deleted sources cannot commit stale payloads.
- Pointer move, target resolution, edge auto-scroll, marquee preview, transform
  preview and virtual pinning stay in Rust. Rhai is not invoked per move.
- Related preview signals validate and commit atomically. Canvas scale/rotation
  signals share Motion property ownership and the same affine snapshot used by
  hit testing.
- Retained and delayed callbacks start from a fresh call-depth baseline, fixing
  #80 while synchronous recursion remains bounded.
- Async task/subscription results are preflighted against Rhai's recursive
  delivery limits before callbacks run. Oversized success/error payloads route
  once to a bounded error callback without replaying user code.
- Hosts can add a new collection after mount with
  `ScriptViewHandle::register_native_collection`; `replace_native_collection`
  remains update-only and still rejects unknown names.
- `gpui-rhai check` validates manifests before entry evaluation. Projects with
  declared Host capabilities receive an honest validation level: when `init`
  requires a real Host, neither it nor an initial View that may depend on it is
  executed, and the report says so explicitly.
- Drop targeting follows GPUI clip/occlusion/paint order; rotated marquee
  selection uses the complete affine quadrilateral; Tree validation is bounded
  independently of expansion; virtual realization moves its map without
  copying it through every prefix node.
- Native lifecycle hooks share one reentrancy-safe signal access phase;
  timer/task/subscription renders invalidate gestures through the same commit
  boundary as node events, while presentation-only virtual realization does
  not. Table pointer/keyboard/autofit share cleanup, RangeSlider solves pair
  constraints jointly, and Rotatable pivots follow actual content geometry and
  resize revisions.
- Virtual Sortable renews a logical source lease across offscreen realization
  and connects GPUI `ListState` to native edge auto-scroll. Missing
  NativeCollection reads become exact registration dependencies, Tree ancestor
  navigation is precomputed in Rust, and native Automation waits for the real
  callback result.
- Primitive mount/focus/accessibility/unmount now share the presented retained
  identity. Host-owned Escape reaches offscreen pointer/drag and non-focused
  wheel owners; destination ancestry owns virtual auto-scroll. Virtual row
  components preserve their real callback owner rather than the synthetic row
  namespace.
- Async batches retain every successful commit fact across sibling failures,
  stale effect activations are discarded at delivery time, and online schema
  rejection is fail-fast. Negative collection dependencies are render-only,
  validated and bounded; Tree enabled-ancestor indexing is parent-first.
- RangeSlider preserves legal off-grid endpoints, uncontrolled Table cancel
  restores its previous accepted width, Rotatable uses current styled Canvas
  geometry, and marquee degeneracy is scale independent.

## Integration checklist

1. Upgrade `gpui-rhai`, `gpui-rhai-registry` and `gpui-rhai-cli` together.
2. Run `gpui-rhai update` and review the nine new editable component sources.
3. Keep application position, order, transform, selection, range and expansion
   state controlled; accept or reject the emitted proposal in the Host/Rhai app.
4. Use `DragSource`/`DropZone` for data transfer and `Draggable` for position;
   they are intentionally separate concepts.
5. Run `gpui-rhai gallery --story workbench/interaction-lab` plus the relevant
   focused component stories before application rollout.
6. If `check` reports that Host capability lifecycle validation was not
   executed, its dependent initial View may also be intentionally unexecuted.
   Run the application-owned acceptance fixture with real handlers; the CLI
   deliberately does not fabricate capability success data or init state.

No application needs to raise `RUNTIME_API_VERSION`; it remains 2.
