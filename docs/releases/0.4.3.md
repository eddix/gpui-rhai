# gpui-rhai 0.4.3

Release date: 2026-11-12. A release that is **not compatible** with 0.4.2 in
places, numbered 0.4.3 by the maintainer's choice: read
[Not compatible with 0.4.2](#not-compatible-with-042) before upgrading.
Runtime API stays **3** and MSRV stays **1.99**; the backends move to gpui-pre
0.3.11 and gpui-fast 0.1.13. Upgrade core, registry and CLI together; the new
crate `gpui-rhai-build` joins them.

This release works through the rest of oh-my-traex's feedback on 0.4.2 and the
items an earlier round left for later: one `ScriptView` with the UI embedded
from `build.rs`, a macOS bundle, offscreen screenshots, Select that fits its
options, Markdown tables that lay out by their content, streamed Markdown that
parses only its tail, built-in text in the application's language, local
themes that change what a subtree paints, files dropped from Finder, and the
Lucide icon set. Item numbers below are that feedback's. The full list is in
the [CHANGELOG](../../CHANGELOG.md).

The move to gpui-pre 0.3.11 and gpui-fast 0.1.13 was contributed by
[@javagg](https://github.com/javagg) in #225. nsh-platform-gpui 0.5.0 takes
gpui-fast 0.1.13 too, so oh-my-traex, which links nsh beside gpui-rhai, moves
to both together. Cache islands and scroll layers on gpui-fast are not in this
release.

## GPUI 0.3.11 and 0.1.13 (#225)

gpui-rhai builds on gpui-pre 0.3.11 or gpui-fast 0.1.13, pinned exactly. Their
keystroke API changed: `KeyBindingSpec::to_gpui` takes the `App`, whose keyboard
mapper and operating system a binding loads against, and keystroke text is
parsed for the host's operating system. Scroll handlers take `ScrollEvent`
through `on_scroll`. `gpui-rhai check` expects a Host to pin `=0.3.11` or
`=0.1.13` and names the pin it needs. Thanks to @javagg for the upgrade.

## One ScriptView, embedded from build.rs (#30)

`FileScriptView` and `EmbeddedScriptView` took different builders, so a Host
that read files in development and embedded them for release wrote its mount
twice, and `gpui-rhai embed` wrote the embedded copy once, so a release build
ran whatever `ui/` held when it last ran. One `ScriptView` replaces both:

```rust
let view = gpui_rhai::script_view!().prepare()?;
```

`script_view!()` reads the crate's `ui/` files in a debug build, with hot
reload and `GPUI_RHAI_UI`, and the tree `build.rs` embedded in a release
build. `ScriptView::files(path)`, `::embedded(&UI)` and `::sources(..)` choose
explicitly; `ui_override_env(name)` lets a release build read files from the
path in a variable the Host names. The new crate `gpui-rhai-build` embeds
every file under `ui/` from `build.rs` and asks Cargo to rerun when one
changes; `gpui-rhai init` writes the build script and dependency.

`gpui-rhai bundle` builds a signed `.app` from
`[package.metadata.gpui-rhai.bundle]`: Info.plist with the package version, the
icon converted to icns, `licenses/` and other resources, signed ad hoc or with
`--sign`. `gpui-rhai dev --bundle` runs the debug build inside such a bundle,
where macOS posts notifications and sets the Dock badge, while `ui/` still
reloads from source.

## Offscreen screenshots (#21)

`gpui-rhai shot --out shot.png` renders the application offscreen on the real
macOS renderer and saves PNGs, through the application's own
`examples/shot.rs`, which `init` writes. Steps are flags (`--size`, `--theme`,
`--locale`, `--click`, `--key`, `--wait`, `--out`) or a JSON-lines file in the
automation protocol plus `click`, `keys`, `wait`, `capture`, `theme` and
`locale`. GPUI's `test-support` stays out of release builds: only the
`offscreen-pre` and `offscreen-fast` features turn it on, in dev-dependencies.

## Components (#33, #34, #4, #6, #7, #37, #221)

- A Select without a width fits its widest option and its placeholder, at most
  360 logical pixels, and its list is at least as wide as the trigger
  (`panel_width`). Combobox keeps 280 and takes `width: "content"`.
- A loading Button draws a turning spinner in the label's color, in place of
  its prefix icon or before its label; IconButton swaps its icon for it.
- Select and Combobox take `option_trailing`, a Node factory for content after
  an option's label, such as a Tag with a load figure.
- Tabs takes `variant: "chip"`: separate chips, the selected one raised on a
  bordered thumb (D84). The all-tabs menu trigger has a control's corners.
- Dialog takes `width`, and a dialog stops at 90% of the window: a taller body
  scrolls under the title and above the actions.
- SplitPane's separator is a flush 1px line by default (D85), with a 7px hit
  zone over both panes; `separator: "lane"` keeps the 8px lane. A focused
  handle's grip takes `focus_ring` in either look.

## Markdown (#3, #22, #23, #222)

Tables lay out by their content. Each column fits its widest cell on one line,
within 64 to 360 logical pixels; a longer cell wraps and its row grows. A table
of up to 1,000 cells lays out in full and grows with the document; a larger one
scrolls in `table_max_height` (400 unset) with an always-shown bar.

A streamed reply parses only its tail: a revision that extends the previous
one keeps the blocks before the last one and their highlighting.
`ScriptViewHandle::append_native_text_document` publishes a chunk as the next
revision. Streaming a 125 KB reply 256 bytes at a time took 24.7 s of
preparation and now takes 0.6 s (release build, Apple M5 Pro).

`ctx.scroll_collection_to_key(key, item)` reveals one row of a list that
follows its tail; following pauses until the reader reaches the bottom again.

## Built-in text in the application's language (#31)

Components read their own text through `ctx.t_or(key, fallback)`: button
labels, empty and loading states, search placeholders, accessible names, and
the status lines of the Markdown, code and diff views. The 23 text props that
defaulted to English, such as `empty_text` and `cancel_label`, now default to
`""`, the localized text; a value still wins. The bundled English, Simplified
Chinese and Arabic locales gain 49 keys. None is required: a locale copied
earlier keeps loading and shows English for them until it takes the keys
([locale and RTL](../locale-and-rtl.md#built-in-component-text)).

## Themes (#1b, #18)

A local theme now changes what its subtree paints. `ctx.set_local_theme`
swaps the whole token set at that component: colors, lengths, typography and
motion, in nodes, native primitives and the overlays opened inside it, and the
text color. Before, it only changed what `ctx.theme_variant()` reported
([theming](../theming.md#local-themes)).

`ctx.set_theme_system_pair(light, dark)` follows the system appearance across
families, each argument the `#{ family, name }` map `ctx.theme_variant()`
returns; `ThemePreference::SystemPair` is the Rust form.

## Scripts and check (#11, #12, #14)

- State defaults may be plain Rhai values, typed by the schema:
  `"default": #{ family: "Default", name: "Dark" }`. The tagged form still
  works.
- `gpui-rhai check` fails a literal argument no overload takes, in every
  branch: `style().flex_shrink(0.0)` reports "`flex_shrink` takes (bool), not
  (float)".
- Check defers the capabilities `app.toml` declares, so a component effect
  that starts a subscription no longer fails it.

## Files from the operating system (#28)

A DropZone that lists `os.files` takes the files and folders dragged in from
Finder, once the Host calls `ScriptView::accept_file_drops(true)`. Scripts get
an opaque handle with the name, size and kind of each, never a path; the
Host's capability turns a handle back into the path through
`UiRuntimeState::dropped_files` ([embedding](../embedding.md#files-dropped-from-the-operating-system)).

## Lucide icons (#10)

The registry carries Lucide 1.70.0, 2322 icons. `gpui-rhai add lucide/house`
installs `ui/assets/lucide/house.svg` and Lucide's license in
`licenses/lucide-ISC.txt`, which `bundle` copies into the application; a script
draws it with `image_source(asset("app/lucide/house"))`
([assets](../assets.md#lucide)).

## Not compatible with 0.4.2

- **GPUI.** A Host that names GPUI pins `gpui-pre` `=0.3.11` (or `gpui-fast`
  `=0.1.13`); `gpui-rhai check` rejects the 0.4.2 pins. An application that
  links nsh-platform-gpui moves to 0.5.0. Code on `ScrollWheelEvent` and
  `on_scroll_wheel` moves to `ScrollEvent` and `on_scroll`.
- **ScriptView.** `FileScriptView` and `EmbeddedScriptView` are gone: mount
  `script_view!()` or `ScriptView::files` / `::embedded` / `::sources`.
  `gpui-rhai embed` is gone: add `gpui-rhai-build` as a build dependency and a
  `build.rs` that calls `gpui_rhai_build::embed_ui("ui")`, and delete the
  `src/gpui_rhai_embedded.rs` it generated.
- **Defaults.** A Select without a width fits its options instead of 280
  pixels; SplitPane's separator is the flush line; a loading Button shows a
  spinner and grows by it when it has no prefix icon; Markdown tables lay out by
  content; a dialog stops at 90% of the window. Set `width`, `separator:
  "lane"` or `table_max_height` to keep a former look.
- **Text.** Components show their built-in text in the application's locale,
  and the 23 text props that defaulted to English default to `""`: a script
  that read such a default reads the empty string.
- **Local themes** change painting. A subtree with `set_local_theme` that
  relied on painting in the window's theme reads that theme's colors with
  `ctx.theme_colors`.
- **Accessibility.** An `invisible()` subtree leaves the accessibility tree.
- **Primitives.** `PrimitiveContext::is_focused` reports the host node's focus
  for a primitive without a focus target of its own.
- **Check** fails a literal argument of the wrong type that used to fail only
  when its branch ran.
- **Rust API.** `KeyBindingSpec::to_gpui` takes `&App`. `ThemePreference` and
  `KnownCallDiagnostic` are `#[non_exhaustive]`; `KnownCallDiagnostic` gains `literal_arguments`;
  `OverlayWidthPolicy` gains `AtLeastTrigger`; the CLI library's `ProjectError`
  gains `Bundle`, `ShotMissing`, `EmbedRemoved` and `UnknownLucideIcon`. An
  exhaustive `match` or a struct literal needs the new names. New:
  `ScriptView`, `script_view!`, `EmbeddedUi`, `gpui_rhai::offscreen`,
  `ThemePreference::SystemPair`, `UiContext::set_theme_system_pair` and its
  window and local forms, `text_or`, `CapabilityRegistry::defer`,
  `ScriptView::accept_file_drops`, `DroppedFiles`,
  `ScriptViewHandle::dropped_file_path` and `append_native_text_document`,
  `MarkdownPreparation::prepare_after`, `LiteralArguments`, and
  `gpui_rhai_registry::lucide_icon` with `LUCIDE_ICONS`, `LUCIDE_VERSION` and
  `LUCIDE_LICENSE`.

## Upgrading from 0.4.2

Upgrade the CLI first, then run `gpui-rhai update`. It merges the 34
components this release changed, which take 0.4.3: AlertDialog, Button,
Calendar, Carousel, CodeViewer, ColumnBrowser, Combobox, Command,
CommandDialog, DatePicker, Dialog, DiffViewer, DropZone, IconButton, List,
MarkdownViewer, Pagination, PanZoom, Progress, Resizable, Select,
SelectableCardGroup, SelectableList, SelectionArea, Sortable, SplitPane,
TabOverflowMenu, Table, Tabs, Tag, TimeRangePicker, Timeline, Toast and Tree.
Merges keep local edits and write conflicts to `.gpui-rhai/conflicts/`.

Pin the new GPUI in the Host's `Cargo.toml`, as `gpui-rhai check` reports it,
and move nsh-platform-gpui to 0.5.0 where the application links it. Then move
the Host to one mount: replace `FileScriptView` or
`EmbeddedScriptView` with `script_view!()`, add the `gpui-rhai-build` build
dependency and its `build.rs`, and delete `src/gpui_rhai_embedded.rs`
([production builds](../hot-reload-and-production.md)). For `gpui-rhai shot`,
add `examples/shot.rs` and the `offscreen-pre` (or `offscreen-fast`)
dev-dependency as [visual testing](../visual-testing.md) shows; `gpui-rhai
init` writes them into new projects. Copy the new locale keys from
`registry/locales/` into the application's `ui/locales/` to translate the
built-in text.

`tests/native-keyboard` on both backends and for the apps; `cargo doc` with
warnings denied on both backends; the workspace tests (911 on each backend),
the default-feature library tests (641), the native suite (726 on gpui-pre,
also with every subtree an island, and 714 on gpui-fast with scroll layers
off), all `tests/native-keyboard` tests (727), the token reload tests (5), the
CLI's tests (78) and the apps' tests (51). Rust 1.99.1, the latest stable,
passes strict Clippy and the workspace tests (911) on both backends. #225 at
its head and each of the 24 code commits after it, exported on its own, pass
the full gate: format; strict Clippy for the workspace, the library alone and
`tests/native-keyboard` on both backends; the workspace tests; the app
component check; the native suite on gpui-pre in both island modes and on
gpui-fast; and, from `gpui-rhai shot` on, the test-support check and the
offscreen tests and screenshot.

`gallery_profile`: `Window::draw` p95 at most 3.64 ms over every interaction,
within the 8.3 ms budget.

Visuals: gpui-pre 0.3.11 places some glyphs a fraction of a pixel differently,
mostly in titles and bold or large text, and keeps a CJK full stop off the
start of a line. 47 of the 57 committed baselines were recaptured for the glyph
positions; the other 10 render identical. Every Gallery page in both densities
was compared in RGB with 0.4.3 on gpui-pre 0.3.9: 84 of 102 differ in each, by
glyph positions and, on the Scrolling page, by that line break; no layout,
color or size changed. Compared with 0.4.2, Button and IconButton also show
the loading spinner (#34), MarkdownViewer's table fits its columns (#3, #222),
the SplitPane page shows the flush separator and its new sections (#221), and
the Tabs page shows the chips (#6). The theme appearance probes (light, dark) reported no error and
the appearance lifecycle passed. The release smoke launched its 25 cases and
the artifact audit passed for its 11 binaries. disktree: `key_harness` passes,
and its screenshots in dark and light show the treemap filling the stage beside
the SplitPane panel. `cargo package` packaged and built `gpui-rhai-build`,
`gpui-rhai` and `gpui-rhai-registry`; with Lucide the registry crate is 716 KiB
compressed. The third-party license inventory lists 691 resolved packages
with default features and none without license metadata.

Real windows, on macOS 27.0.1 with the [real-window
scripts](../../scripts/macos-real-window/): Tab moves the focus frame across the
Button page; the command palette opens with its input focused, takes key codes
as text, and under a Chinese input method as marked text whose composition the
first Escape cancels; copy, paste and cut follow the pasteboard; the Table's
menu opens at the pointer and, with Shift+F10, under the selected row; a drag
from the density control leaves the window in place, and a click selects the
density.
SplitPane, PanZoom, Rotatable and Draggable show the committed position right
after release, and nothing moves when the pointer leaves. In one run PanZoom
did not move on a drag 4 seconds after its page opened; two reruns, 5 seconds
after opening, moved it as expected. In `multi_window` the
shared count reaches both windows while a draft stays in one, the close request
asks with a Dialog that shows its focus frame, Tab, Tab and Return close the
window, a reopened window takes a theme of its own, and the other window keeps
its theme. The title bar moves the window and a double press zooms it; on
macOS 27 a synthetic drag lags the pointer and its release tiles the window to
the top half of the screen, with 0.4.2 as with 0.4.3.

One binary: oh-my-traex's application builds with nsh-platform-gpui 0.5.0 and
gpui-rhai 0.4.3 on one gpui-fast 0.1.13. Its tree holds no gpui-pre core or
platform crate; gpui-fast 0.1.13 itself uses gpui-pre's utility crates, and
its platform names gpui-pre-ios for iOS builds only, which `gpui-rhai check`

Upgrade: a copy of oh-my-traex, whose 35 modules earlier CLIs installed, passes
the 0.4.3 check as it is. Of the 14 changed modules it uses, `gpui-rhai update`
merged 13 and reported one conflict, in Combobox, which oh-my-traex had
