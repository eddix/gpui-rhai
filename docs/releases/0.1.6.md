# gpui-rhai 0.1.6

Status: implementation candidate; not yet published.

0.1.6 keeps Runtime API **2** while replacing the Rust GPUI package family and
connecting gpui-rhai's retained semantics to the operating system accessibility
tree. Existing Rhai applications remain source-compatible; Rust Hosts must
migrate their dependency identity and toolchain.

## GPUI backend and Host migration

- The exact backend family is `gpui-pre 0.3.6` plus
  `gpui-pre-platform 0.3.6`, traced to Zed commit
  `bcf6582ce3500df93a8a39366640173e6786cea6`.
- The declared MSRV is Rust 1.95. Standalone applications now enter through
  `gpui_platform::application()`; `ScriptApplication` keeps the same public
  standalone behavior.
- `gpui-rhai::gpui` and `gpui-rhai::gpui_platform` are the recommended Host
  imports. A direct Host dependency must alias the same exact packages; official
  `gpui 0.2.2` types cannot compose with this release.
- `gpui-rhai check` detects old or mixed dependency families and prints the
  required declaration without editing `Cargo.toml`.
- macOS uses runtime Metal shader compilation in the current candidate so an
  ordinary crates.io build does not require the separately downloaded Xcode
  Metal Toolchain. Cold-start and failure behavior remain release gates.

## Native accessibility

- A validated, immutable `CommittedSemanticFrame` is accepted in the same
  transaction as the retained UI tree. Automation and GPUI/AccessKit consume
  this shared semantic frame; committed presentation geometry is joined without
  reparsing roles or state.
- Native projection covers localized labels/descriptions, stable author IDs,
  selected/expanded/toggled/current state, scalar and numeric values, ranges,
  orientation, required/invalid/disabled/read-only state, placeholders,
  shortcuts, set positions and table row/column metadata.
- Unknown roles reject the candidate before commit. Presentation-only nodes do
  not enter the native tree.
- AX Click and Focus use GPUI's foreground/window dispatch. Input, Textarea,
  Slider and Chart add generation-bound native primitive actions; changes still
  travel through their existing controlled callbacks.
- Table, Command and Combobox publish bounded realized collection metadata.
  Chart retains a bounded active/selected summary rather than materializing all
  large-data marks.

## Existing behavior retained

- The 51-component source foundation, theme/style system, Motion Runtime 2,
  Chart Runtime, HostSlot, hot reload and capability boundaries remain owned by
  gpui-rhai; this release does not adopt Kit/Base/Component or a second Runtime.
- Window visibility does not silently suspend a ScriptView. Motion continues to
  use the existing active-time policy and Host-owned reduced-motion preference.
- The SVG adapter remains a complete-document, background-prepared path for
  currentColor, fonts and bounded variants. The obsolete double channel-swap
  workaround is not reintroduced.

## Upgrade checklist

1. Upgrade `gpui-rhai`, `gpui-rhai-registry` and `gpui-rhai-cli` together.
2. Install Rust 1.95 or newer.
3. Replace direct official GPUI dependencies using the exact declarations in
   [Embedding](../embedding.md), or import the runtime's public re-exports.
4. Run `gpui-rhai update`, review the component semantic source changes, then
   run `gpui-rhai check`.
5. Re-test Host-owned custom primitives that implement focus, value or bounded
   synthetic accessibility behavior.

## Remaining release blockers

- `gpui-pre 0.3.6` predates upstream wrapped-line hit-test fix #64672. 0.1.6
  will not publish from a family with a known reachable text panic.
- macOS VoiceOver, CJK IME, runtime-shader cold start, Linux X11/Wayland native
  smoke and both agreed dogfooding applications must complete the maintained
  release matrix.
