# 0.4.3 计划（2026-11-06 确认）

0.4.2 处理了 oh-my-traex（下称 omt）对 0.4.0 反馈里最急的部分，并加上 gpui-fast 后端。剩下的反馈，加上原本打算「之后再做」的四项，全部放进 0.4.3，不再往后排。条目编号沿用 omt 反馈的编号；GitHub issue 用 `#2xx`。发布前要用 omt 实际验证。

这是一轮工作的计划：0.4.3 发布时，把长期有效的内容并进正式文档，本文件移出目录树并登记到 [History](../history.md)。

## 顺序

按 omt 的急迫程度排，打包放第一位：

1. 打包与离屏：#30、#21
2. 组件：#33、#34、#4、#6、#7、#221、#3/#222
3. 接口与开发体验：#22、#23、#31、#18、#14、#11、#12、#28
4. 原定之后再做的：#1b、Lucide 图标、GPUI 升级与 gpui-fast 原生支持（有条件，见下文）

## 默认行为

0.4.2 定下「默认行为现在就改，不做成可选项」，其中以下四项留到本版：

- Select 默认宽度跟内容走（#33）
- SplitPane 默认贴线分隔（#221）
- Button `loading` 默认画转圈（#34）
- 组件内置文案走语言包（#31）

## GPUI 升级（有条件）

一个二进制里只能有一份 gpui-fast。nsh-platform-gpui 目前最新是 0.4.0（2026-11-04），依赖 `gpui-fast ^0.1.9`，在 0.1.11 及以后编不过（`KeyBinding::new` 改为要 `'static`）。gpui-rhai 如果先升，omt 的单二进制就会断。

- 0.4.3 发布前 nsh 发布了基于 gpui-fast 0.1.13 的版本：本版升到 gpui-pre 0.3.11 + gpui-fast 0.1.13，并把 MSRV 下限核对为 1.98。
- 否则：在分支上备好适配，nsh 升级后的那个版本再发。已评估的工作量：`action.rs` 4 处（动态串 `Keystroke::parse`、`KeyBinding::load` 末参变为 `&App`），以及 16 条 `ScrollWheelEvent` / `on_scroll_wheel` 弃用警告。
- 版本约束：gpui-fast 0.1.13 依赖 gpui-pre 基础 crate `=0.3.11`，两者必须一起升。

gpui-fast 上的 cache island 和滚动层原生支持（列表改由 `ListState` 驱动，宿主不再需要 `GPUI_SCROLL_LAYERS=0`）跟在升级之后做，免得在 0.1.9 和 0.1.13 上各写一遍。
